osb · OS builder

Describe the machine. osb writes the scripts.

Say what a system should be – users, packages, services, a desktop, certificates – in one high-level YAML file. osb turns it into readable, idempotent shell scripts, Dockerfiles and cloud-init, and builds container images, WSL distributions and VM images from it. The same file works on Ubuntu, Debian and Arch Linux.

How it works

From intent to artifacts

osb evaluates the configuration at generation time – arguments, JavaScript expressions, conditions, flavors – into a plan of simple operations. Renderers map them to the native features of each target and fall back to a small, readable shell library.

Describe

YAML with arguments, flavors, imports and steps that use high-level actions.

  • add-user
  • install-aur-package
  • letsencrypt-certificate
→

Validate & evaluate

JSON schema, types and patterns, ${{"{{"}} }} expressions, if, foreach, by-flavor.

→

Plan

Steps of primitive operations: file, packages, user, shell, download…

→

Render & build

Native where possible, shell otherwise.

  • sh → apply
  • Dockerfile → OCI, WSL
  • cloud-init → qcow2, OVA

Why osb

High-level, but no magic

≡

One file, eight outputs

Render a shell script, a Dockerfile or cloud-init, or build an OCI image, a WSL distribution, a qcow2 or an OVA – or apply it to the running machine after showing the plan.

⇄

Flavors

Ubuntu, Debian and Arch Linux, plus your own derived flavors. Generic package names are mapped; by-flavor picks values where distributions differ.

✦

High-level actions

47 built-in actions and a library of extra actions written in YAML: install-aur-package (pinned), krdp-server, letsencrypt-certificate, plasma-autologin…

ƒ

Expressions

One language – JavaScript – in one delimiter: ${{"{{"}} args.user }}. Conditions, loops, outputs of earlier steps and validations run at generation time.

⧉

Libraries & tests

Write your own actions, import them from files or git (pinned in a lockfile) and test them with osb test – golden files and runs in real containers.

✓

Safe by default

Errors with file:line, secrets masked everywhere and passed as BuildKit secrets, idempotent scripts, and osb apply asks before it changes anything.

⌁

Readable output

No agent and no runtime: the generated POSIX shell script is plain, commented and dependency-free. Read it, review it, run it anywhere.

▣

A single binary

Actions, the shell library and the JSON schema for editor completion are compiled in. Linux and macOS, amd64 and arm64.

Get started

Install the binary

curl -fsSL https://github.com/SvenTo/osb/releases/latest/download/osb_linux_amd64.tar.gz | tar -xz osb
sudo install osb /usr/local/bin/
osb init my-machine && cd my-machine
osb render shell --flavor debian       # print the script
osb build oci --flavor ubuntu          # build a container image
osb build qcow2 --flavor archlinux     # build a VM image
sudo osb apply                         # configure this machine

Downloads for Linux and macOS are on the releases page. Next: Getting started · Builder · All actions
